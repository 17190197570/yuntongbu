## 免费签名的前置条件

依据 SignPath Foundation 的官方条款（https://signpath.org/terms）：所有组件应使用
合规开源许可证、项目持续维护、已有所申请格式的发布版本、功能和隐私行为公开说明，
且可执行软件需有可核实的信誉。**新建仓库和首次开源不保证获得批准，也没有承诺获批时间。**
申请入口：https://signpath.org/ 。账户注册、协议接受、身份/项目审核和最终发布批准
由仓库所有者完成；不向聊天提供密码、MFA、私钥或签名 API token。

批准后按官方要求配置以下内容：

1. 注册项目、维护者与签名批准人，确认组织/项目/策略标识及 GitHub 构建来源。
2. 固定构建流程和依赖版本，启用保护规则；只接收对应受审核提交构建的自有文件。
3. 给所有自有 EXE/DLL/MSI 设置并限制正确的 ProductName/CompanyName/FileDescription。
   当前流程尚未完成全部原生二进制元数据与签名制品配置，不能直接作为签名生产线。
4. 生成完整二进制第三方许可清单，保留上游签名，不重新签名上游库或任意外部二进制。
5. 在受保护的发布任务中提交可验证的构建制品；手动批准签名；下载签名结果并独立验签、
   校验时间戳和预期发布者，然后在 Windows 测试安装、启动和 CFAPI/SMB。
6. 获批并接入后，按基金会要求在主页和下载页增加其指定的代码签名归属说明。

当前 `.github/workflows/ci.yml` 只负责公开构建与本地 fixture 测试，上传验证日志；
没有签名令牌、没有自动发布，也没有声称已完成 SignPath 的来源证明集成。

## 已有证书时的本地入口

`scripts/sign-artifacts.ps1` 接受当前用户证书存储中的代码签名证书指纹、HTTPS 时间戳服务
及明确指定的自有 EXE/DLL/MSI；签名后独立验签。该脚本不生成受信任证书，也不要求传入
私钥或 PFX 密码，不能代替基金会的托管签名流程。

当前错误 `0x800711C7` 仍需在取得符合策略的签名后重新验收。自签、改名或复制程序集
不能作为通过安全策略的替代方案。签名确认来源和完整性，不代表完整功能或数据安全已验收。
